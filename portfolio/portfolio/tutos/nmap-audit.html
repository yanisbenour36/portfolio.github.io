Nmap : cartographier et auditer un réseau

Nmap repère les machines d’un réseau, leurs ports ouverts et les services qui tournent. Ce lab l’utilise pas à pas sur des machines virtuelles prévues pour s’entraîner.

Durée : environ 3 hNiveau : débutant à intermédiaireMachines : Kali, Ubuntu Server, Windows 10, Metasploitable2

Avant de commencer

  • Règle d’or : ne scannez que vos propres machines, les VM du TP ou une cible pour laquelle vous avez une autorisation écrite. Un scan non autorisé peut être puni par la loi (article 323-1 du Code pénal). scanme.nmap.org est une cible officielle pour s’entraîner.
  • Quatre VM sur un réseau isolé 192.168.56.0/24 : Kali .10, Ubuntu Server .20, Windows 10 .30, Metasploitable2 .40.

Les étapes

  1. Scanner votre propre machine (Kali)

    -sV détecte la version des services, -oA enregistre le résultat en trois formats.

    nmap localhost
nmap -p 22,80,443 localhost
nmap -sV localhost
mkdir -p ~/nmap-lab/results
nmap -oA ~/nmap-lab/results/localhost localhost

  2. Découvrir les machines du réseau

    -sn est un « ping » seul : il liste les machines actives sans toucher à leurs ports. -n supprime la résolution DNS et accélère le scan.

    nmap -sn 192.168.56.0/24
nmap -F -oA scan-initial 192.168.56.10-50
time nmap -sn 192.168.56.0/24
time nmap -sn -n 192.168.56.0/24

  3. Auditer le serveur Ubuntu

    On scanne, on constate, on corrige, on re-scanne : c’est la boucle d’audit. Ici, on interdit la connexion directe de root en SSH.

    nmap -sV 192.168.56.20
nmap -sC -sV 192.168.56.20
curl -I http://192.168.56.20
nmap --script vuln -p 22,80,443 192.168.56.20

# sur le serveur : PermitRootLogin no dans /etc/ssh/sshd_config
sudo systemctl restart ssh
nmap --script ssh-auth-methods -p 22 192.168.56.20

  4. Auditer le poste Windows 10

    Le pare-feu Windows rend beaucoup de ports « filtered » : un port filtré peut cacher un service actif. -Pn force le scan même si la machine ne répond pas au ping.

    nmap 192.168.56.30
nmap -Pn 192.168.56.30
nmap -sV -p 135,139,445,3389 192.168.56.30
nmap --script smb-os-discovery -p 445 192.168.56.30

  5. Analyser Metasploitable2 (réseau isolé uniquement)

    Cette VM est volontairement vulnérable : ne l’exposez jamais hors du réseau du lab. Repérez la ligne signalant la porte dérobée connue de vsftpd 2.3.4. Toute démonstration d’exploitation se fait avec l’accord de l’enseignant.

    nmap -sV -sC -p- 192.168.56.40 -oA metasploitable-scan
nmap --script vuln -p 21,22,23,25,80,139,445,3306 192.168.56.40

  6. Voir l’effet de la vitesse avec Wireshark

    Lancez Wireshark sur Kali, filtrez sur ip.addr == 192.168.56.20, puis comparez le rythme des paquets envoyés. Un scan lent (-T0) est plus discret, mais très long.

    sudo nmap -sS -T5 192.168.56.20
sudo nmap -sS -T0 192.168.56.20

Vérifier que ça marche

Pour interpréter un résultat :

nmap --reason 192.168.56.30

Chaque port a un état (open, closed, filtered) et --reason explique pourquoi Nmap a conclu ainsi.

À retenir

  • Ouvert : un service écoute. Fermé : la machine répond, rien n’écoute. Filtré : un pare-feu bloque, on ne sait pas.
  • Sans -p, Nmap ne teste que les 1000 ports les plus courants : utilisez -p- pour tout vérifier.
  • -sS demande les droits administrateur (sudo) ; sans eux, utilisez -sT.
  • Un audit finit par un rapport : machines trouvées, commandes utilisées, vulnérabilités, corrections.
