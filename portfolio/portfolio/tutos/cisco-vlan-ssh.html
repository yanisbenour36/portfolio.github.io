Sécuriser un switch Cisco : mot de passe, SSH et VLAN

Un switch neuf n’a ni mot de passe ni protection : n’importe qui peut le brancher et le reconfigurer. Ce tuto le transforme pas à pas en équipement sécurisé, avec deux réseaux séparés (VLAN) et un accès d’administration chiffré (SSH).

Durée : environ 1 h 30Niveau : débutantOutil : Cisco Packet Tracer

Avant de commencer

  • Un switch Cisco 2960 et trois PC : PC1 sur Fa0/1, PC2 sur Fa0/2 et PCA (administration) sur Fa0/3.
  • Plan d’adressage : VLAN 1 (gestion) 192.168.1.0/24 avec le switch en 192.168.1.1 ; VLAN 10 « SALES » 192.168.10.0/24 ; VLAN 20 « ADMIN » 192.168.20.0/24.

Les étapes

  1. Nommer le switch et protéger le mode privilégié

    enable secret stocke le mot de passe chiffré, contrairement à l’ancien enable password.

    enable
configure terminal
hostname SW1
enable secret cisco123
banner motd #UNAUTHORIZED ACCESS IS PROHIBITED#

  2. Protéger la console et l’accès à distance

    La console est l’accès physique par câble ; les lignes vty 0 15 sont les 16 connexions possibles à distance. On exige un mot de passe et on coupe une session inactive après 10 min 30.

    line console 0
 password cisco
 login
 exec-timeout 10 30
 logging synchronous
exit
line vty 0 15
 password cisco
 login
 exec-timeout 10 30
 logging synchronous
exit

  3. Activer SSH

    SSH chiffre la connexion, contrairement à Telnet. L’ordre compte : le nom de domaine doit exister avant la clé RSA. Taille de clé : 1024 dans le TP, 2048 conseillée aujourd’hui.

    ip domain-name sisr.local
crypto key generate rsa
username admin secret cisco
line vty 0 15
 login local
 transport input ssh
exit
ip ssh version 2

  4. Chiffrer les mots de passe restants

    Cette commande masque les mots de passe de type « password » dans la configuration. Le chiffrement est faible, mais évite un coup d’œil indiscret.

    service password-encryption

  5. Créer les VLAN et y brancher les PC

    Un VLAN découpe le switch en réseaux séparés : PC1 et PC2 ne peuvent plus se parler directement (il faudra un routeur).

    vlan 10
 name SALES
vlan 20
 name ADMIN
exit
interface fa0/1
 switchport mode access
 switchport access vlan 10
interface fa0/2
 switchport mode access
 switchport access vlan 20
exit

  6. Protéger le port de PC1 (port-security)

    Seule la première adresse MAC vue sur Fa0/1 est acceptée. Un autre appareil coupe le port (état err-disabled). Pour le rallumer : shutdown puis no shutdown.

    interface fa0/1
 switchport port-security
 switchport port-security maximum 1
 switchport port-security mac-address sticky
 switchport port-security violation shutdown
exit

  7. Donner une adresse IP de gestion

    Un switch n’a pas besoin d’IP pour commuter, mais il en faut une pour l’administrer à distance.

    interface vlan 1
 ip address 192.168.1.1 255.255.255.0
 no shutdown
exit
ip default-gateway 192.168.1.254
end

  8. Sauvegarder

    Sans cette étape, toute la configuration disparaît au redémarrage.

    copy running-config startup-config

Vérifier que ça marche

Sur le switch :

show vlan brief
show port-security
show port-security interface fa0/1
show ip ssh

Depuis PCA, la connexion SSH doit demander le mot de passe et s’ouvrir ; Telnet doit être refusé :
ssh -l admin 192.168.1.1

À retenir

  • Les pièges classiques : oublier no shutdown sur l’interface VLAN 1, créer la clé RSA avant le nom de domaine, laisser transport input all.
  • Les mots de passe « cisco » servent à l’entraînement : en entreprise, on en choisit de longs et uniques.
  • Pour tester le port-security, branchez une machine différente : le même PC ne déclenche rien.
