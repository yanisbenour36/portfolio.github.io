Diagnostiquer une panne de connexion réseau

Un poste « n’a plus Internet ». Plutôt que deviner, on teste dans l’ordre : configuration, réseau local, Internet, nom de domaine. Chaque test élimine une cause possible.

Niveau : débutantSystème : Windows

Avant de commencer

  • Un terminal CMD sur le poste en panne.

Les étapes

  1. Lire la configuration

    Relevez adresse IPv4, masque, passerelle, DNS et la carte active. Une adresse en 169.254.x.x signifie que le DHCP n’a pas répondu ; sans passerelle, pas d’accès extérieur ; sans DNS, les noms de sites ne se résolvent pas.

    ipconfig /all

  2. Tester dans l’ordre

    127.0.0.1 OK : la carte et la pile réseau fonctionnent. Passerelle KO : problème local (câble, switch). Passerelle OK mais 8.8.8.8 KO : problème vers Internet. 8.8.8.8 OK mais google.com KO : problème de DNS.

    ping 127.0.0.1
ping 192.168.1.254
ping 8.8.8.8
ping google.com

  3. Suivre le chemin

    Chaque ligne est un routeur. Une étoile signifie pas de réponse (souvent un filtrage ICMP sans gravité). Un délai qui explose ou des pertes montrent un point de congestion.

    tracert google.com

  4. Regarder les connexions

    netstat -ano relie chaque connexion à un numéro de processus ; on retrouve celui-ci dans le Gestionnaire des tâches.

    netstat -ano

  5. Tester le DNS

    Interroger un DNS externe isole un problème de DNS interne.

    nslookup google.com
nslookup microsoft.com 8.8.8.8

  6. Réparer

    Renouveler l’adresse, vider le cache DNS, réactiver la carte, puis réinitialiser la pile réseau en dernier recours (redémarrage nécessaire).

    ipconfig /release
ipconfig /renew
ipconfig /flushdns
netsh interface show interface
netsh int ip reset
netsh winsock reset

Vérifier que ça marche

Après réparation :

ping google.com

Reprenez les pings dans l’ordre pour confirmer le retour de la connexion.

À retenir

  • Méthode : du plus proche au plus lointain.
  • nslookup peut réussir quand ping échoue si un pare-feu bloque ICMP.
